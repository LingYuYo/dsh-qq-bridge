# dsh-qq-bridge

> 把 QQ 接进 [DeepSeek Harness](https://github.com/deepseek-ai) 的陪伴型桥接。
> 纯 Node.js，零外部依赖：包含纯原生编写的桥接底座与插件面板，数万行纯源码（不含测试）。
> 当前版本 v0.5.5 · 2026-10-27

<br>

## 🐳 项目定性

QQ 那头有人在说话，DSH 这头有一个会记事、也知道分寸的 agent，中间这层桥负责让两边都不失真。

它不是群发机器人，也不是给 API 套个壳。它记得谁说过什么，也清楚自己不该做什么。

<br>

## 🎯 核心架构

四层，各管一件事。层与层之间不互相借道，出事的时候能指认是哪一层的问题。

| 层 | 干什么 | 落点 |
|:--|:--|:--|
| 👁 **感知** | 消息进来先拆开：长图切片、视频抽帧、引用链、合并转发、B 站元数据。全部手写解码，不借外部服务 | `qq-bridge/src/onebot.mjs`、`image-prep.mjs` |
| 🎚 **治理** | 决定这一轮给模型看多少：Token 预算按模型窗口滑动（128K～1M）、模型无痕热切、动态信息只追加在尾部 | `model-override.js`、`tokens.mjs` |
| 🧠 **记忆** | 未读归纳（合并转发输出）、水位推进。读到哪由证据判定，不由模型声明 | `unread-summary.mjs`、`state/sessions.json` |
| 🛡 **安全** | 主人／管理员两阶权限；Fail-safe 降级：看门狗切断挂死的流、失败重试与回退 | `tools.guard`、`index.js` |

<br>

## 🛡️ 已站住的强项

### 1️⃣ 消息隔离，不串台

群里两个人几乎同时说话，防抖合并会把它们并成一轮，而一轮只能挂一个引用。

现在的做法是：换人就切批，投递那一刻把 `message_id` 快照固化。之后无论谁再开口，都只能开新的一轮，改不到已经投出去的那份。

**保证的是**：谁说的话进谁的轮次，引用指回原消息，并发也不串。

### 2️⃣ 纯手写长图切片解码

长截图不是一张图，是一段被压扁的对话。手机长截图（1080×10000 这种）会先撞上附件准入的硬上限，直接被 DSH 拒收。

`image-prep.mjs` 的做法：只读文件头拿尺寸，不为了「看看多大」去解码整张图；超限了才解码，按长边切条，相邻两条留 64px 重叠，避免一行字被切在缝上；最多切 6 条。

解码器是自己写的（`png-codec.mjs` / `jpeg-decode.mjs`），压缩只用 `node:zlib`。实在处理不了就认输，给一句准确的话：「图片太长，请拆分后发送」，绝不让模型对着空白猜。

**保证的是**：群友甩一张长截图过来，读得到，也读得全。

### 3️⃣ 权限死守红线

工具门禁 deny-by-default，执行期白名单兜底；权限只认事件里的 QQ 号。

改昵称、在正文里写「我是管理员」、让模型自己宣称自己是主人，一条都提不了权。

**保证的是**：边界写在代码里，不写在提示词里。

## 🚧 正在攻克的四件事

不按功能排，按短板排。

### 🧹 一、记忆治理

**现状**：未读归纳的水位机制已实现，但目前长期记忆只进不出，缺少删除／遗忘／撤销入口。摘要只增、印象没有有效期，删没删干净没有证据。

**判据**：有删除／遗忘入口；删完检索 0 命中；每日备份，分钟级可恢复；误写能事务化撤销。

**做法**：删除按消息序号与时间范围两种粒度；有效期按数据类型分开（原话／摘要／印象）；撤销先写意图，再改索引。

### 🌙 二、主动行为

**现状**：消息驱动。没人说话，它基本不存在。现有的唤醒是按空闲时间做的采样，不是连续状态，也不留决策理由。

**判据**：低频 tick 先只感知、只记录、不行动；连续 8 小时无消息仍有记录；可一键停，每次决策可回溯。

**做法**：tick 间隔 10～30 秒，多数轮次什么都不发；先把理由写进独立日志，再讨论要不要接发送链路。

### 🔑 三、开发者特权

**现状**：两阶（主人／管理员）够用，但要调试就得看内部链路、临时开口子，现在只能改代码。

**判据**：特权是第三阶，只在私聊与单会话内有效，随时可收回；群消息里任何文本都触发不了它。

**做法**：特权走独立签名，不写进 Prompt，不进工具白名单，权限判定与聊天内容彻底分开。

### 🏷 四、置信度标注

**现状**：分不清「记得」「看到」和「猜到」。图里大概有，会被说成图里有。

**判据**：回答带来源（记忆／观察／推断）；抽样 50 条，标注正确率 ≥90%；猜错能降权并回写。

**做法**：条目加 `confidence` 字段；提示层要求标来源，解析后进事件日志；错了按条目降权，而不是只写一句「下次注意」。

## ⚠️ 边界与红线

1. **前缀缓存保护**：时间、未读、模型路由这类每轮都变的东西，只追加在 Prompt 尾部，绝不重排前缀。前缀一改，缓存全废，延迟和成本一起炸。任何「顺手把提示词整理一下」的改动，先过这一条。

2. **权限只认 QQ 号**：不看昵称、不看正文、不看模型输出。

3. **聊天与模型输入一律不可信**：不得变成命令、任意路径、URL 或 OneBot 动作。

4. **失败退到安全侧**：看图失败就说看不到，绝不猜；发送失败持久化重试；配置坏了保留上一份有效。

5. **不扩大行动面**：要扩，先有白名单、本人确认和独立的停止开关。

6. **不宣称意识**：对外说法是，一个有记忆、有边界的程序。

## 🚀 快速开始

```bash
# 1) 插件以 link 方式装进 profile
dsh plugin --profile desktop add "link:<repo>/plugins/dsh-qq-guard"

# 2) 重启 DSH（bundle 层要重启才组装）

# 3) 桥接：复制配置再改
cp qq-bridge/config.example.json qq-bridge/config.json
node qq-bridge/start.mjs --dry-run   # 只校验配置和 DSH 鉴权
node qq-bridge/start.mjs             # 正式启动
```

前提：Node ≥ 22、NapCat 开着正向 WS、DSH 桌面端在跑。

`allow` 留空 = 谁都不理，这是刻意的默认值。
